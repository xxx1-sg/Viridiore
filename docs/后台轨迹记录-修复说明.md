# 后台轨迹记录 · 修复说明

## 一、问题现象与根因

现象：轨迹页记录的路线是一条**直线**（截图：9.20 km / 14:30 / 平均配速 1'34"，约 38 km/h）。

根因（已在代码中确认）：

1. App 用的是 **WebView 的 `navigator.geolocation`**（`src/services/geo.js` 的 `watchPosition`），没有接入原生定位插件。
2. Android 清单只有 `ACCESS_FINE/COARSE_LOCATION`，**没有** `ACCESS_BACKGROUND_LOCATION`、**没有**前台服务；iOS 也没有 `UIBackgroundModes = location`。
3. 一旦**锁屏 / 切后台**，系统会暂停 WebView，`watchPosition` 不再回调 → 中间所有点都丢了，只剩「开始」和「回来」两个点，两点相连就是直线。
4. 原有采点逻辑还有两个次要问题：`accuracy > 80m` 直接丢弃（容易一点不留）；没有跳点剔除，一个坏点就能把线拉出去很远。

## 二、这次改了什么

### 1) 原生后台持续定位（核心）

- 新增 Android 前台服务 `LocationTrackingService`：用系统 `LocationManager`（GPS + 网络）按 **1 秒 / 1 米** 持续采集，锁屏和后台都不停。
- 新增应用内 Capacitor 插件 `BackgroundLocationPlugin`：暴露 `start / stop / getLocations / clear / isTracking`。
- 采集点先写入**原生内存缓冲** `LocationBridge`。因为 WebView 在后台会被挂起、无法即时收到事件，所以改为「**原生缓冲 + JS 定时拉取(drain)**」：回到前台后一次性取回后台那一段，完整重建真实路线。
- `MainActivity` 注册插件；`AndroidManifest.xml` 增加 `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_LOCATION` / `ACCESS_BACKGROUND_LOCATION` / `WAKE_LOCK` 和 `foregroundServiceType="location"` 的服务声明。

### 2) 前端采集层（`src/services/tracker.js` + 新增 `src/services/location.js`）

- 原生环境：走后台服务 + 每秒 drain 原生缓冲；非原生（浏览器/PWA/桌面）仍用 `watchPosition`，并尽量加 **Wake Lock** 防止屏幕休眠。
- 采点去重（按时间戳）、精度过滤（>100m 丢弃，但首个点保留）、**GPS 跳点剔除**（速度 > 90 m/s ≈ 324km/h 判为异常）。

### 3) 绘制层（`src/components/mapview.js` + `src/pages/trail.js`）

- 轨迹支持**多段折线**：时间断档（>90 秒）或异常跳变处**断开**，不再把「不知道中间怎么走」的两段连成一条假直线。
- worker 的距离计算也同步跳过跳点，避免距离虚高。

### 4) iOS

- `Info.plist` 已加 `UIBackgroundModes = location`。
- 新增 `ios/App/App/BackgroundLocationPlugin.swift`（与 Android 同接口）。**需在 Xcode 里把该文件加入 App target**（见下）。

## 三、如何验证（Android，推荐先测这个）

1. 重新出包：
   - 用仓库里 `.github/workflows/android-apk.yml`（Actions 手动触发），或本地 `npm run mobile:android`。
2. 安装后打开「轨迹」→ 点「开始记录」：
   - 首次会请求定位权限，请选**允许**。
   - **Android 11+ 注意**：如果只给了「仅在使用时允许」，请到
     `设置 → 应用 → 晓山青 → 权限 → 位置 → 改为「始终允许」`，
     这样后台才能一直记录。
3. 开始后通知栏会出现常驻通知「晓山青 · 正在记录轨迹」，代表前台服务在跑。
4. **锁屏或切到其他 App**，正常走路/开车；回来点「结束并保存」。
5. 看轨迹：应当沿真实路线，而不是一条直线。

> 若某机型仍然只采到零星几个点：多半是厂商省电策略把后台服务杀了。请在系统「电池 / 后台管理」里把晓山青设为「不限制 / 允许后台活动」。

## 四、iOS 接入（需要 macOS + Xcode，一次性）

1. 用 Xcode 打开 `ios/App/App.xcworkspace`。
2. 把 `ios/App/App/BackgroundLocationPlugin.swift` 拖进左侧 `App/App` 分组，勾选 **App target**。
3. 确认 `Info.plist` 中 `UIBackgroundModes` 含 `location`（已配好）。
4. 首次开始记录时按提示授予「始终允许」定位。
5. Capacitor 6 会自动发现实现了 `CAPBridgedPlugin` 的本地插件，无需手动注册。

## 五、可调参数（想更省电 / 更精细时）

- 采样间隔/距离：`LocationTrackingService.java` 中 `requestLocationUpdates(..., 1000L, 1f, ...)`（毫秒 / 米）。
- 精度阈值：`src/services/tracker.js` 的 `MAX_ACCURACY_M`（默认 100 米）。
- 跳点阈值：`MAX_SPEED_MPS`（默认 90 m/s）。
- 断段阈值：`src/pages/trail.js` 的 `GAP_MS`（默认 90 秒）。

## 六、已知限制

- 若 App 进程被系统整体杀掉（极端省电策略），后台那一段会丢失——需要更重的「原生持久化 + 开机恢复」才能彻底兜住，可后续再做。
- iOS 未在 Xcode 加入插件文件前，会自动回退为前台定位（不会崩，但后台不记录）。
- 本次前端已通过 `vite build` 打包校验；原生 Java/Swift 需在具备 Android SDK / Xcode 的环境实际编译验证。
